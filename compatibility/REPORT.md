## 每个版本实际验证了什么

- 同一个普通 Fabric 探针先正常安装启动，再在另一个已启动的服务器中加载；验证 Loader 容器、main/server 入口点、JAR 资源与持续 tick 回调。探针不依赖受管模块 API。
- 重复 Mod ID 被拒绝。
- 受管模块 v1 → v2 的功能切换，停用后不能派发命令；100 次 load/reload/disable 循环后资源数为 0、dirty=false、PID 与 session 不变。
- Agent 测试类方法体变换，保留启动 Mixin；新增字段被结构检查器与 JVM 拒绝；恢复原方法体。
- 正常保存与关闭，再启动同一个测试世界；这一重启是保存恢复测试，**不属于前面的热加载操作**。
- 故意初始化失败的普通 Mod 将运行时标记为 DIRTY_RESTART_REQUIRED，并阻止后续激活。

11 个目标合计 **1,100 次受管生命周期循环、143 项服务器检查**。13 项 JVM 单测在每个目标重复运行，并非 143 个不同的单元用例。另有 7 项 Python 分发边界测试、10 项发布/报告测试通过。[实际分发校验记录](../verification/distribution-20261113-multiversion.json)覆盖所有目标的字节码基线、Mixin 等级、intermediary 映射、JAR CRC 与 thin Agent。

没有真实玩家连接。session/PID 不变只证明服务器进程未重启，不能证明玩家必然不断线、零卡顿或类加载器已完全回收。

## 修复与安全降级记录

1. 旧版依然写着 JAVA_25 的 Mixin 配置，实际 JDK 17 启动失败；改为按目标生成 JAVA_17/21/25 后重测。Java 17 公共运行时替换了 List.reversed 等新接口，逆序关闭与失败后继续清理有单测。
2. 1.20.4 的 tick 平均值接口已切换到纳秒，不能与 1.20.1 共用毫秒实现；独立适配后完成服务器检查。
3. 1.18.2 的 Maven Fabric API 主 JAR 是依赖壳，缺少运行模块，曾出现 ServerLifecycleEvents 的 ClassNotFoundException；测试改为 SHA1 校验的完整运行包，并验证嵌套 lifecycle 模块。上游下载地址与校验值固定在 targets.json。
4. [1.19.2 / Loader 0.18.4 安全降级实测](../verification/integration-20261113T124331536040Z-mc1.19.2.json)：普通热加载在提交前拒绝，容器未添加、dirty=false；受管模块 100 次循环与 Agent/保存重启仍通过。这**不代表**已适配 0.18.4 的普通 Mod 热加载。其他未知 Loader 只具备代码层面的关闭策略，未逐一实测。
5. [首次多版本 GitHub CI](https://github.com/41kewen/fabric-hotload/actions/runs/43430252942)：Linux 的 11 个构建/测试完成；Windows 构建完成，但临时目录的 8.3 别名造成分发路径集合误判。统一规范路径，并添加两个路径归一化回归测试；此修订不修改已经通过服务器测试的 JAR。

## 未完成与明确限制

- **真实第三方 Mod 兼容性尚未实测**；普通探针通过不等于多数 Mod 可热加载。
- 普通 Mod 仅实验性新增，不支持通用卸载、更新、初始化副作用回滚；Mixins、类访问变换、嵌套 JAR 等候选被拒绝。
- 冻结注册表、网络通道、客户端同步、启动事件补跑、自动命令同步、任意资源包集成没有通用方案。
- Linux 服务器运行、在线玩家持续连接、完整 JVM 类卸载未验证。GitHub Linux/Windows CI 只构建与执行单元/边界测试，不运行 Minecraft。
- 更早版本（例如 1.16.5）的 Java/API 差异需要单独适配与实际服务器测试，不能通过放宽元数据宣布支持。

## 复现、扩展与恢复

构建、运行入口和 EULA 要求见 [README](../README.md)。新增版本先添加 targets.json 中的精确基线，选择或新增 MinecraftPlatform，再通过构建、分发检查与同一服务器探针；未通过的目标不得作为已支持版本发布。CI 从 targets.json 读取目标，不维护另一份版本列表。

原始输入、stdout、退出状态存放在开发机 verification/raw/，包含测试世界关联信息与本机路径，不随开源包发布；这里的 JSON 是保留哈希及实际关键输出的公开摘要。源码修改前的额外快照与 SHA256 在开发机 history/multiversion-start-20261113T121548Z/ 保留。

回退源码可在**新的目录**检出旧标签 v0.1.0-p0；它仅支持原来的 26.2 基线。回退部署需正常保存并关闭服务器，保留当前 JAR 和操作日志，然后使用匹配版本的旧产物或世界备份。运行时停用/字节码恢复不会撤销世界数据变化，也没有通用热回退。
